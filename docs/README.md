# ballware Ml Service — documentation

This folder documents the Ml Service from the backend side: its HTTP API surface, request/response
payloads, model lifecycle (definition → training → prediction), tenancy and authorization behavior,
outbound service dependencies, and the OpenAPI snapshots the pages are derived from.

> Scope note: this is the **backend view** of the service. Setup, configuration and operational
> troubleshooting live in the repository [README.md](../README.md) and are not duplicated here.
> The tenant-facing metadata definitions (`meta.mlmodel` entity metadata, pages, rights catalogs) are
> authored in a separate metadata repository and are referenced here only as conventions.

## Quick facts

- Two OpenAPI documents per deployment: `ml` ("ballware Ml user API", 15 paths, 6 schemas) and
  `service` ("ballware Ml service API", 3 paths, 3 schemas), OpenAPI `3.0.4`
  (`src/Ballware.Ml.Service/Startup.cs:291-301`).
- Swagger UI: `https://localhost:6003/swagger`; raw documents at `/swagger/ml/swagger.json` and
  `/swagger/service/swagger.json` (`src/Ballware.Ml.Service/Startup.cs:373-389`,
  `src/Ballware.Ml.Service/appsettings.Development.json:8-20`).
- Committed OpenAPI snapshots: [openapi/ml.json](openapi/ml.json), [openapi/service.json](openapi/service.json),
  generated by [openapi/fetch-spec.sh](openapi/fetch-spec.sh).
- All routes are mounted under `/ml`: `/ml/mlmodel/...` and `/ml/tenant/...`
  (`src/Ballware.Ml.Service/Startup.cs:362-366`).
- Authentication: JWT bearer against an OIDC issuer; authorization by scope → policy
  (`mlApi` for user API + editing operations, `serviceApi` for service API operations,
  `src/Ballware.Ml.Service/Startup.cs:139-153`).
- JSON bodies are PascalCase (`src/Ballware.Ml.Service/Startup.cs:168-176`); enums serialize as
  integers (see [api/schemas.md](api/schemas.md)).
- Model definitions live in the service's **own** storage database (`mlmodel` / `ml_model` table),
  not in the Meta Service database — the Meta Service supplies metadata, rights and export/job
  records ([concepts/architecture.md](concepts/architecture.md)).
- Training runs asynchronously in a Quartz job; predictions are served from a tenant-scoped in-memory
  prediction-engine cache ([concepts/model-lifecycle.md](concepts/model-lifecycle.md)).

## Request flow

```text
client (browser / other ballware service)
  |  Authorization: Bearer <token>
  v
ASP.NET Core routing + JWT bearer authentication            Startup.cs:123-137
  |  scope claim -> policy "mlApi" / "serviceApi"           Startup.cs:139-153
  v
endpoint handler
  |  user API + editing handlers take the tenant from the
  |  "tenant" claim; service API handlers take an
  |  explicit {tenantId} path segment                       MlModelEndpoint.cs / TenantEndpoint.cs
  v
editing handlers only: tenant + entity rights check         ballware-shared-dotnet
  |  candidate "meta.mlmodel.<right>" evaluated by the
  |  tenant RightsCheckScript, then by the entity
  |  CustomScripts.extendedRightsCheck                      EditingEndpointBuilder.cs:66-115
  v
Ml storage (EF Core, mssql | postgres)                      Startup.cs:271-279
  |  model definitions: mlmodel table
  v
engine: AutoML train / predict                              AutoMlExecutor.cs
  |  training rows  -> Generic Service (plain query)        GenericServiceTenantDataAdapter.cs
  |  model artifact -> Storage Service (attachment)         StorageServiceFileStorageAdapter.cs
  |  metadata/rights/exports/jobs -> Meta Service           MetaServiceMetadataAdapter.cs
  |  all three with OAuth2 client-credentials tokens        Startup.cs:188-251
```

For setup and configuration see the repository [README.md](../README.md). For OpenAPI regeneration see
[openapi/README.md](openapi/README.md).
